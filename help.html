From an idea
to a shared request.

This is the lightweight companion to Outdoor Design Studio. Your answers describe a design direction; a detailed layout is prepared and reviewed afterward.

Fill it out

  1. Name the idea and optionally add your name.
  2. Open whichever of the six sections matter to you. Tap an option in each visible list. Leave “Undecided — propose” selected when you want a recommendation. “None” is an explicit exclusion.
  3. Use Optional details for dimensions, extra appliances and finish variations. Desired sizes are proposals, not new site measurements.
  4. Read the short explanation above each choice list. Open its Notes / additions / customizations area for colors, sizes, patterns or another design. Review & share has just Designer notes and Overall request / custom details.
  5. Tap Review request. Resolve any contradictions you can; unresolved items remain visible for design review.

Save & send

Changes automatically save in this browser when valid. Check the save indicator. Saving does not synchronize between devices.

  1. Tap Download JSON. On a phone, find the file in the browser’s Downloads or the Files app.
  2. Send that file to your spouse to relay for rendering. Share request uses the phone’s sharing menu where supported; it may share text if JSON file sharing is unavailable.
  3. Keep the JSON as your backup. Draft tools → Import mobile JSON reopens it in this mobile form.

Copy request and Download text also preserve the readable brief, but only JSON reopens all editable choices. The web address itself contains no selections.

Start a new idea and Import both retain one previous draft on this device. Restore previous draft swaps it back. Download separate JSON files to keep more ideas.

Full Studio13 scenario exports do not import here. Mobile briefs use outdoor-mobile-brief/1; they require a reviewed layout before conversion to a full Studio13 request and Blender rendering. They never create placeholder positions.

Use it while traveling

  1. Open the published HTTPS link in Safari or Chrome while online.
  2. Wait for “Ready offline on this device.” That confirms this version’s form files are cached.
  3. Optionally add the link to the Home Screen. In iPhone Safari use Share → Add to Home Screen; in Android Chrome use its menu’s Add to Home screen / Install option.
  4. Before relying on it during a trip, turn on airplane mode, reopen the form in the same browser/app and check that your draft remains.

The first load needs internet. Browser storage can be cleared or evicted; private browsing is not a durable workspace. Export a JSON backup before changing browsers or devices. Home-screen apps and browser tabs may have separate storage.

When an update is available, tap Save & reload. No login, home computer or Blender installation is required to fill out the published form.

Publish with GitHub Pages

Use a computer for this one-time setup. You need a GitHub account. No terminal, paid plan, custom domain or build command is needed.

  1. Extract Outdoor-Mobile-Brief-GitHub-Pages.zip. Inside it, open the site folder.
  2. Sign in at github.com/new. Name a new repository outdoor-design-brief. Choose Public, turn on Add README, then create it.
  3. In the repository’s Code tab, choose Add file → Upload files. Select the contents of the site folder. Upload the individual files, not the ZIP or its enclosing folder. No nested folders are needed.
  4. Commit the files to the main branch. Confirm that index.html, catalog.js, brief.js, app.js, style.css, sw.js, help.html, manifest.webmanifest, icon.svg, icon-192.png and icon-512.png appear at the repository’s top level. Include .nojekyll if your file picker shows it; these plain files also work if that optional empty file is omitted.
  5. Open Settings → Pages. Under Build and deployment, set Source to Deploy from a branch.
  6. Choose main and /(root), then click Save.
  7. Wait for GitHub’s deployment to complete. The Actions tab shows its progress. Return to Settings → Pages and click Visit site. Publication can take several minutes.
  8. Your link will normally be https://YOUR-USERNAME.github.io/outdoor-design-brief/. Keep the trailing slash. Use GitHub’s actual Visit site link rather than guessing. Ensure the HTTPS setting is enabled if offered.
  9. Open the link on the phone. Choose a few options, reload, download a JSON, then import that file to verify the complete handoff. Check offline use as described above.

You can send that public link to your wife. Her selections stay in her browser until she exports or shares them. GitHub hosts the application files; this form has no server submission endpoint.

Updates & troubleshooting

To publish a later release, upload the new site folder’s contents into the same repository and commit to main. The URL stays the same. Keep the repository name stable; a different address uses different draft storage.

  • 404: check main, /(root), and that index.html is at the top level rather than inside site/. Check the Actions tab.
  • Unstyled or blank form: some files may be missing. Upload the complete site contents.
  • Offline setup unavailable: use the published HTTPS address, wait online for the ready indicator and confirm all files were uploaded. Opening a downloaded HTML file is only a preview.
  • Old version: reconnect, reopen the page and use the update button when it appears. Export JSON before clearing browser storage.
  • Import stopped: use a JSON from this mobile form, under 1 MB, with the matching baseline/catalog. Invalid or full-studio files are rejected without replacing the active draft.
  • Dimension error: enter a positive desired size between 1 and 100 feet, or leave blank. Invalid values cannot be exported.
  • Share unavailable: download JSON and attach it manually, or copy the text.

Publishing steps checked against GitHub’s site setup guide and branch publishing guide. Offline support follows the Service Worker API; sharing follows the Web Share API. Browser controls and labels can vary.
